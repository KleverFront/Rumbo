Rumbo — Arquitectura (macOS)

App de escritorio local. Los datos y las claves se quedan en la Mac del usuario; solo sale a internet para consultar portales de empleo y el proveedor de IA que el usuario eligió.

1. Diagrama

2. Flujo principal

  1. Perfil: el usuario sube su CV (PDF/DOCX). Se extrae el texto y la IA lo estructura una sola vez como JSON (experiencia, habilidades, estudios).
  2. Buscar: cada adaptador consulta su portal y devuelve ofertas en un formato común. Se eliminan duplicados por empresa + cargo + ciudad.
  3. Match / ATS: se calcula localmente, sin IA y sin costo, cruzando las palabras clave de la oferta con el CV base.
  4. Adaptar: solo cuando el usuario lo pide, la IA reescribe el CV para esa oferta con la regla «no inventar experiencia». También genera el skill gap y la carta de presentación.
  5. Exportar: el CV en JSON se pasa por una plantilla y se genera el PDF.
  6. Seguimiento: la oferta pasa al kanban, con recordatorios por notificación de macOS.

4. Por qué este stack

  • Tauri en vez de Electron o Python embebido: genera una .app de unos 10 MB que usa el WebView de macOS. Xolva baja Python con pip en cada instalación; esto no.
  • Sin Playwright ni scraping masivo: se usan APIs públicas. LinkedIn queda solo como «pegar un enlace», así no se arriesga la cuenta del usuario.
  • El match se calcula local y la IA solo corre a pedido: así el costo queda bajo control y la app funciona aunque no haya clave cargada.
  • Claves en el Llavero de macOS y sin telemetría (Xolva manda eventos a su servidor).

5. Fases

  1. Mockup aprobado (este documento + mockup.html).
  2. Esqueleto Tauri + SQLite + navegación.
  3. Perfil: importar CV → JSON.
  4. Fuentes: Remotive y Adzuna primero; luego el resto.
  5. Match/ATS local.
  6. Motor IA (un proveedor primero, luego más) + adaptar CV + exportar PDF.
  7. Kanban de postulaciones + recordatorios.
  8. Empaquetado .dmg + repo en GitHub.

⚠️ Antes de la fase 4 hay que verificar si Computrabajo y Multitrabajos permiten consultar sus ofertas por API o feed, o revisar sus términos de uso. Si no lo permiten, se usa «pegar enlace».

6. Alcance v1 y preparación para v2 (copiloto de postulación)

v1: buscar ofertas → match/ATS → CV adaptado + carta → kanban. El formulario de postulación lo llena el usuario.

v2 (no se construye ahora): una extensión de Chrome/Safari que rellena los formularios con el perfil, adjunta el CV adaptado y propone respuestas a las preguntas abiertas. El usuario siempre aprieta «Enviar».

Decisiones de v1 para que v2 se pueda agregar sin rehacer nada:

  • Perfil estructurado: el perfil se guarda como campos tipados (contacto, experiencia, estudios, idiomas, pretensión salarial, disponibilidad), no como texto libre. La extensión los usará para mapear los campos de cada formulario.
  • CV adaptado guardado por oferta: la tabla applications guarda el JSON y el PDF generado, listos para adjuntar.
  • Banco de respuestas: se crea desde v1 la tabla answers (pregunta, respuesta, oferta), aunque todavía no tenga pantalla.
  • Núcleo separado de la UI: los comandos Rust (perfil, CV, IA) no dependen de React. En v2, la extensión los llama por native messaging o un puerto local con token.
  • Motor IA con tareas nombradas (parse_cv, adapt_cv, cover_letter; el skill gap se calcula local, sin IA). En v2 se agrega answer_question sin tocar lo demás.

7. Estado de la v1 (2026-10-29)

  • Hecho: perfil tipado + importar CV (PDF/DOCX) + completar perfil con IA; búsqueda en Remotive y Adzuna + oferta pegada a mano; compatibilidad y ATS locales; CV adaptado con IA, carta de presentación y PDF; kanban con estados y recordatorio de seguimiento a 7 días; claves en el Llavero; límite de gasto mensual.
  • Proveedores de IA: Claude (Opus 5.5 por defecto, con respaldo automático del servidor si el modelo rechaza una solicitud), DeepSeek, Gemini y Ollama. OpenAI quedó fuera.
  • LinkedIn: se lee su búsqueda pública sin iniciar sesión (decisión del usuario, 2026-10-29). Va contra sus términos de uso; no se usa navegador automatizado ni se disfraza el tráfico. Si LinkedIn cambia su HTML o limita las consultas, deja de funcionar.
  • Otros portales (Indeed, Computrabajo, Multitrabajos): bloquean el acceso automático (Cloudflare). Se abren dentro de Rumbo en una ventana aparte; el usuario navega normalmente y el botón «Importar esta oferta a Rumbo» envía la oferta. Sin automatización ni evasión.
  • Fuera de la v1: Jooble, Computrabajo y Multitrabajos (falta revisar si tienen API o qué permiten sus términos; mientras tanto, «pegar oferta»); búsqueda automática diaria; resaltado de diferencias palabra por palabra entre el CV base y el adaptado; arrastrar tarjetas en el kanban; firma y notarización del .dmg.
